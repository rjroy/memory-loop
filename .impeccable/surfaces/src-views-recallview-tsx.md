### State and action contract

| State / action | Visible result and retained state |
|---|---|
| Reading → Edit | Preserve current reading position and initialize source from the exact loaded note plus its daemon revision. Show Cancel/Save and focus the textarea without opening the phone keyboard on mere file selection. Start at source top; do not pretend rendered and source offsets correspond. |
| Editing, unchanged | Save remains visible but unavailable; Cancel returns to reading without confirmation. Dirty means exact string inequality against the saved base, including whitespace. Returning to the base text clears dirty. Empty Markdown is valid. |
| Editing, dirty | Show Unsaved changes; enable Save. No write until explicit Save or its keyboard equivalent. Native editing, undo, selection and copy remain intact. |
| Save requested | Capture the exact file ID, source, base revision and draft generation. Button reads **Saving…**, prevents duplicate requests, and exposes busy state. Textarea stays editable. Cancel and same-view departures wait for the outcome; show **Saving… Please wait before leaving.** if departure is attempted. Do not imply Cancel can undo an accepted write. Browser unload protection remains active while a save is unresolved. |
| Save confirmed, draft unchanged since request | Render the confirmed saved source with the existing Markdown renderer, return titlebar to Edit, announce **Note saved.**, restore the prior reading position clamped to the new body, and focus Edit when focus still belongs to the completed action/editor. Do not clear an error or claim success before confirmation. |
| Save confirmed, newer typing exists | Stay in edit mode with all newer text, cursor and source scroll intact. Advance the saved base/revision only to the acknowledged source. Show Unsaved changes; announce **Saved. Newer changes are not saved yet.** No second automatic save. |
| Known save rejection | Stay in edit mode. **Couldn't save this note.** — **Your draft is still here. Try saving again.** Keep text, selection, source scroll and original revision; Save becomes available for an explicit retry when the failure is retryable. Missing/unwritable files instead explain **This note may have moved or is no longer writable. Your draft is still here.** Do not recreate a missing file. |
| Transport/uncertain outcome | **Save not confirmed.** — **Your draft is still here. Check the connection and try saving again.** Never say the disk was unchanged when that is unknown. A deliberate retry must retain the original revision fence; uncertainty never authorizes an overwrite or automatic replay. A stale retry follows the conflict state below. |
| External-change conflict | **This note has changed since you opened it.** — **Your draft is still here. Copy any changes you want to keep, then reload the saved note.** Keep textarea editable/selectable, but make Save unavailable with an associated reason. Offer **Reload saved note**; it opens the same explicit discard confirmation before replacing anything. No overwrite, force-save, silent rebase, merge UI or save-as. |
| Confirmed reload after conflict | Read the current saved note and replace the draft/base only after a successful read. On success return to rendered reading and announce **Saved note reloaded.** On read failure keep the draft and show **Couldn't reload this note. Your draft is still here.** An unresolved reload does not open an overwrite path. |

Place one save/reload recovery message above the textarea in its lane, not in a toast or replacing the whole workspace. Keep it selectable, wrapping and associated with the editor; use a concise live announcement, never the source body. Error text uses readable Ivory with explicit wording; bright Ember is reserved for the destructive discard action. Do not steal focus from ongoing typing when an asynchronous response arrives. Reading empty/error/renderer states remain otherwise unchanged. Remove the now-false unselected-state sentence **Notes open read-only.**; keep **Open a folder or choose a file in Files.**

### Draft safety and navigation

- Keep the active draft, file identity, revision, source selection/scroll and pending-save ownership in the persistent Recall session, not only in the route component. No draft text in URL/history, logs, localStorage or sessionStorage; no durable/offline recovery promise. Mount changes, responsive pane changes and stale callbacks must not erase it.
- Before a dirty Cancel, different-file selection, app destination change, programmatic same-view navigation or Back/Forward departure that would abandon/replace the edit, hold the original destination and show one full-width inline confirmation immediately below the titlebar, before either pane. It must remain visible when phone Files is open. Do not mutate the selected identity/body, close Files, fetch the next note or commit navigation first.
- Confirmation copy: **Discard unsaved changes?** / **Your changes to “{filename}” haven't been saved.** Buttons: **Keep editing** (initial focus), **Discard changes** (bright Ember text/border on dark). Filename wraps as text. Keep editing or Escape dismisses the confirmation, cancels the pending departure and returns to the textarea with selection/scroll restored, revealing the phone editor if necessary. Confirming discards once and performs only the originally requested action; pending requests cannot stack or switch destinations under the confirmation.
- A confirmed dirty Cancel exits editing and restores the last acknowledged rendered source/read position; focus Edit. A confirmed different-note/tab/history departure uses existing destination focus/scroll rules. Reload saved note uses the same confirmation but applies its read-success safety above. No third Save-and-leave action or implicit save is added.
- Showing/hiding Files, folder disclosure, tree refresh, same-note reveal, focus-only pane jumps, same-content hash changes and switching the browser's active tab do not abandon the draft and do not prompt. In edit mode, clicking the already-selected file reveals the existing editor rather than rereading/resetting it. Phone Files temporarily hides the editor without unmounting its session draft; header editing actions still refer to the named file. A different file triggers the guard before the existing close-on-selection behavior.
- Native file links and modified/new-tab activations stay native: opening another tab does not abandon this draft. Another browser view's save is an external change and must be revision-checked. Hard reload, closing the browser tab/window or leaving the document uses native `beforeunload` protection only while dirty or saving; browser-owned wording is not customizable. Never rely on tab blur/visibilitychange to save or discard.
- Guard at the shared presentation boundary, not just file-row `onClick`: app links, router intents and native traversal all matter. No new history entry for Edit/Save/Cancel, no URL edit mode, no history ping-pong on dismissal, and no regression to existing selected-note, hash and per-entry scroll restoration. If a browser cannot cancel a traversal safely, that is an implementation blocker to resolve, not permission to drop the draft.
