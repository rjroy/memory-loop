# Recall daemon contract

The daemon loads `.memory-loop/config.json` relative to the project root once at startup. Its JSON object has a `vaultDirectory` string containing a nonempty absolute directory path. Changes require restart; configuration lives outside the vault and is not returned to clients. Missing and malformed configuration, and an unavailable vault, remain distinct from an empty tree.

The daemon endpoints are private and authenticated; browser requests go through the Next server boundary. The daemon serves no frontend assets or SPA fallback and needs no frontend build. `GET /api/vault/tree` returns `VaultTreeResponse`; `GET /api/vault/note?id=...` returns `VaultNoteResponse`. `POST /api/vault/note` saves an existing Markdown note with its expected revision. `POST /api/vault/actions` creates, moves or deletes an entry as described below. Types and public error codes are in `contract.ts`. The `id` parameter is the URL-encoded JSON representation of a nonempty array of filename components, e.g. `id=%5B%22folder%22%2C%22note.md%22%5D`. Use normal URL query encoding exactly once; reject duplicate `id` parameters, malformed JSON, and non-string or empty components. Reject `.`, `..`, slash, backslash, NUL, absolute paths, and dot-prefixed components individually, not separators between components. IDs returned in tree entries can be passed back unchanged after query encoding; clients must not construct host paths. The note endpoint accepts only regular `.md` files.

On failure return `{ "error": { "code": "...", "message": "..." } }`, with no host path or note content. Use 400 for `invalid_request`, 404 for `note_unavailable`, and 503 for `config_missing`, `config_invalid`, or `vault_unavailable`. Action errors and their statuses are defined in `contract.ts`. Do not silently substitute an empty tree. An empty configured vault returns an empty `entries` array and a `rootIdentity`. API responses use `Cache-Control: no-store` and `X-Content-Type-Options: nosniff`. The daemon requires the configured bearer credential and exact daemon Host, and rejects any Origin or Fetch Metadata headers. Missing or invalid private transport is fatal before vault access. It binds only to numeric loopback; no browser credential injection or remote exposure is provided.

The nested tree includes only directories and Markdown notes, excludes dot entries and symlinks, and sorts deterministically. Unreadable directories must surface an error rather than claim a complete tree. Paths and note content must not enter logs.

## Saves and file actions

The tree supplies an opaque root identity and an identity and version for each entry. Note reads supply a revision bound to the physical file and its bytes. These tokens are scoped to the opened vault reader and are invalidated by daemon restart. After a conflict or restart, refresh the relevant tree or note and reconcile the user's work before attempting another change.

Actions create a blank `.md` note or empty directory under an identified parent, move a note or whole directory to an identified parent with the same basename, or delete a note or a verified-empty directory. Root parent IDs are empty arrays; source IDs are nonempty. Requests include the expected parent identity or source version. The backend does not add a missing `.md` extension. Moves never overwrite a destination or fall back to copying and deleting; deletion of directories is nonrecursive and refuses hidden or non-Markdown contents too. The daemon serializes saves and actions through the vault queue.

A known failure does not authorize a destructive retry. If an acknowledgement is lost or a post-mutation flush fails, the outcome is uncertain: do not automatically repeat the request. Reconcile with a fresh read instead.

Moves use Linux `renameat2(RENAME_NOREPLACE)` through an isolated Bun FFI adapter against glibc. Bun FFI is experimental. If the required runtime, platform or operation is unavailable, moves fail closed; cross-device moves are refused rather than copied. This is not a portable move implementation.

## Linux namespace boundary

Trust the configured root and its ancestors, the local OS and the personal vault namespace; this is not a sandbox against hostile local processes. Pin the root directory object until daemon restart. For each request, hold descendant directory descriptors while opening individual components relative to them using Linux procfs and no-follow semantics; reject entry symlinks, including replacement during component open. Open note files nonblocking and check the opened descriptor is a regular file before reading. Close request-scoped descendants and the root at shutdown. If Linux/procfs or required capabilities are unavailable, fail as unavailable; never fall back to pathname-prefix or pre-open realpath checks.

Hardlinked regular files in the vault are eligible: no provenance guarantee is made. An already-open directory relocated outside the root may finish an in-flight operation; ordinary rename/delete can produce unavailable results and the tree is not a transactional snapshot. An earlier local capability probe was not retained as independent race evidence; behavior and failure boundaries still need verification against controlled fixtures. The daemon remains loopback-only; browser access uses the Next boundary.
