### State and action contract

| State / action | Visible result and retained state |
|---|---|
| Reading → Edit | Preserve current reading position and initialize source from the exact loaded note plus its daemon revision. Show Cancel/Save and focus the textarea without opening the phone keyboard on mere file selection. Start at source top; do not pretend rendered and source offsets correspond. |
| Editing, unchanged | Save remains visible but unavailable; Cancel returns to reading without confirmation. Dirty means exact string inequality against the saved base, including whitespace. Returning to the base text clears dirty. Empty Markdown is valid. |
| Editing, dirty | Show Unsaved changes; enable Save. No write until explicit Save or its keyboard equivalent. Native editing, undo, selection and copy remain intact. |
| Save requested | Capture the exact file ID, source, base revision and draft generation. Button reads **Saving…**, prevents duplicate requests, and exposes busy state. Textarea stays editable. Cancel and same-view departures wait for the outcome; show **Saving… Please wait before leaving.** if departure is attempted. Do not imply Cancel can undo an accepted write. Browser unload protection remains active while a save is unresolved. |
| Save confirmed, draft unchanged since request | Render the confirmed saved source with the existing Markdown renderer, return titlebar to Edit, announce **Note saved.**, restore the prior reading position clamped to the new body, and focus Edit when focus still belongs to the completed action/editor. Do not clear an error or claim success before confirmation. |
| Save confirmed, newer typing exists | Stay in edit mode with all newer text, cursor and source scroll intact. Advance the saved base/revision only to the acknowledged source. Show Unsaved changes; announce **Saved. Newer changes are not saved yet.** No second automatic save. |
| Known save rejection | Stay in edit mode. **Couldn't save this note.** — **Your draft is still here. Try saving again.** Keep text, selection, source scroll and original revision; Save becomes available for an explicit retry when the failure is retryable. Missing/unwritable files instead explain **This note may have moved or is no longer writable. Your draft is still here.** Do not recreate a missing file. |
| Transport/uncertain outcome | **Save not confirmed.** — **Your draft is still here. Check the connection and try saving again.** Never say the disk was unchanged when that is unknown. A deliberate retry must retain the original revision fence; uncertainty never authorizes an overwrite or automatic replay. A stale retry follows the conflict state below. |
| External-change conflict | **This note has changed since you opened it.** — **Your draft is still here. Copy any changes you want to keep, then reload the saved note.** Keep textarea editable/selectable, but make Save unavailable with an associated reason. Offer **Reload saved note**; it opens the same explicit discard confirmation before replacing anything. No overwrite, force-save, silent rebase, merge UI or save-as. |
| Confirmed reload after conflict | Read the current saved note and replace the draft/base only after a successful read. On success return to rendered reading and announce **Saved note reloaded.** On read failure keep the draft and show **Couldn't reload this note. Your draft is still here.** An unresolved reload does not open an overwrite path. |

Place one save/reload recovery message above the textarea in its lane, not in a toast or replacing the whole workspace. Keep it selectable, wrapping and associated with the editor; use a concise live announcement, never the source body. Error text uses readable Ivory with explicit wording; bright Ember is reserved for the destructive discard action. Do not steal focus from ongoing typing when an asynchronous response arrives. ### Draft safety and navigation

It must remain visible when phone Files is open. Do not mutate the selected identity/body, close Files, fetch the next note or commit navigation first.

- Showing/hiding Files, folder disclosure, tree refresh, same-note reveal, focus-only pane jumps, same-content hash changes and switching the browser's active tab do not abandon the draft and do not prompt. No new history entry for Edit/Save/Cancel, no URL edit mode, no history ping-pong on dismissal, and no regression to existing selected-note, hash and per-entry scroll restoration. ### Draft safety, pending state and recovery

- Reuse the persistent n72 editor and `editor.request()` guard before a command that abandons, moves or deletes its file, including a folder move containing that file, or creation that will open a new file. No mutation, URL remap or draft discard before this decision. **Keep editing** cancels the operation and reveals/focuses the existing editor with its selection/scroll. **Discard changes** resumes only the captured operation; do not add Save-and-leave or auto-save. The dirty guard is separate from explicit deletion confirmation; capture deletion intent first, then guard before submission without stacked surfaces.
- Menus, disclosure, destination browsing, folder creation and operations on unrelated entries preserve the current draft without prompting. A clean editor may finish when its selected identity is successfully replaced/removed. Saving/reloading blocks conflicting operations with the existing wait message, not a broad ban on selected-file actions. Fence affected editor writes while a submitted move/delete is unresolved so later typing cannot be silently lost; unrelated drafts remain editable.
- On submission retain the dialog/target, show **Creating…**, **Moving…** or **Deleting…**, expose busy state and suppress duplicate/conflicting submissions. Cancellation is available before submission; after submission it must not imply an accepted filesystem mutation can be undone. Never optimistically remove a row or claim success. Async completion must not steal focus after the user moved elsewhere.
- Known rejection keeps names/destination and a local recovery message. Collision: **An item with this name already exists in that folder. Choose another name or folder.** Stale source: **This item has changed. Refresh files before trying again.** Do not expose host paths or raw filesystem errors.
- Unconfirmed outcome: **Creation / Move / Deletion not confirmed. Refresh files to check what happened before trying again.** Retain the affected source/destination fence until an explicit read-only reconciliation; no automatic destructive retry, repeated POST on refresh/reconnect, invented success, or newly built generic job system. A tree reread is not permission to delete whatever later occupies the same path: revalidate identity/revision before any fresh deliberate command. Failure/uncertainty never drops an undiscarded draft.
