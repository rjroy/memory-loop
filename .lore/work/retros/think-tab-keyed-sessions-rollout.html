Think-tab keyed live sessions rollout (phases 3-5)

The Think tab had a wrong-session bug: the daemon tracked the in-flight chat turn in a single global "active session" slot, so resuming an older conversation B after streaming conversation A could surface A's events under B, or persist the wrong session id. The plan (.lore/plans/think-tab-keyed-sessions.md) replaced the singleton with per-session live state keyed by id in the URL path, mirroring the sibling project oracle-keep: client-minted session ids, event-buffer replay on reconnect (no snapshot wrapper), warm session reuse, and send+stream folded onto one keyed /chat route. Six phases: 0 registry skeleton, 1 turn controller, 2 daemon routes, 3 Next.js proxy + daemon client, 4 frontend useChat/reducer, 5 cleanup + docs + manual smoke test.

This retro covers phases 3 through 5. Phases 0-2 were already committed and green at the start (HEAD = 23324d5).

Surprises and dead ends

Dead end (prior session): flaky tool channel → "sub-agents didn't persist." A replayed stale git status showing a clean tree drove the conclusion that sub-agent file writes never landed, then a "stale contract.ts" theory built on files that were never real (Read returned "File does not exist" for both). Hours of false reasoning and a corrupted work-notes file. The recovery that worked: re-verify each fact with a direct single command, cross-checked, and stop trusting the agent-reported state. From that point all work used direct tools.
Surprise: the abort test broke even though abort() was byte-identical to HEAD. The regression came from upstream, not the abort code. With client-minted ids, sendMessage now seeds sessionIdRef synchronously before the POST. Previously the id only existed after the server's session_ready arrived. The abort test's POST mock was delayed 5000ms, so at HEAD session_ready never came, sessionIdRef stayed null, and abort() skipped its server call — going straight to idle. After the change, the id was always present, so abort() always awaited the abort fetch, which the test's coarse mock (5000ms delay on every URL) hung. Fix: the mock now fast-paths /abort like the real daemon. A test-fidelity gap exposed by a real behavior change, not a production bug.
Surprise: 1969 passing tests + a clean build, app crashes on the first send. crypto.randomUUID() is only defined in a secure context (HTTPS or http://localhost). Memory Loop is served over plain HTTP on a LAN IP, where crypto.randomUUID is undefined even though crypto and crypto.getRandomValues exist. Nothing in the bun/node test environment or the build reproduces a non-secure browser context. The fix uses randomUUID() when present and otherwise builds a v4 UUID from crypto.getRandomValues(); generated ids pass the daemon's validateSessionId character rules.

Context worth preserving for the next session here

  • Client-minted ids changed abort/stream timing. Any test or code that assumed "no session id until session_ready" is now wrong. The id exists synchronously from the first sendMessage call. Mocks that delay all fetches will hang the abort/permission/answer paths, which now always call the server.
  • Secure-context APIs are a standing hazard in this app. It runs over plain HTTP on a LAN IP. crypto.randomUUID and crypto.subtle are unavailable there. nextjs/lib/uuid.ts now exists for ids; reach for it rather than crypto.randomUUID. Audit any future use of secure-context-gated web APIs against this deployment.
  • Replay replaced snapshot end to end. There is no snapshot wrapper event anywhere now. Reconnect replays raw turn events through the same reducer actions as live events. HANDLE_SNAPSHOT, handleSnapshot, pendingSessionId, and REPLACE_LAST_MESSAGE_CONTENT are gone.
  • Remaining work. Smoke test steps 2-5 are un-run (resume-B-only, two-tab independence, mid-turn reconnect, tool-permission/AskUserQuestion). Then holistic validation against the plan. The daemon-side collision guard for a client-supplied id of a new session (flagged in the plan's risks) was not separately verified in the smoke test.
  • Doc drift found along the way. .lore/reference/think.md's file map still pointed at pre-daemon-split paths (nextjs/lib/controller.ts, backend/src/...) that predate this work. Corrected to the real daemon modules.
